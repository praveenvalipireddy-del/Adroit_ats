MASTER RESUME OPTIMIZATION & JD ALIGNMENT PROMPT

Objective:

Analyze the provided Job Description (JD) and Resume thoroughly, calculate the realistic match percentage, and intelligently optimize the resume only when the profile is sufficiently relevant. The goal is to improve ATS alignment while maintaining resume authenticity, recruiter trust, and timeline realism.

CORE DECISION LOGIC

STEP 1: INITIAL MATCH ANALYSIS

First analyze:

- Mandatory skills match

- Recent project relevance

- Role alignment

- Domain alignment

- Tools/framework/cloud match

- Years of experience relevance

- Certifications/education relevance

- Architecture/platform relevance

Calculate a realistic overall match percentage.

Weighted Match Logic:

- Mandatory Skills → 40%

- Recent Project Relevance → 25%

- Domain Experience → 15%

- Tools/Frameworks/Cloud → 10%

- Certifications/Education → 5%

- Location/Work Authorization → 5%

IMPORTANT:

Do not artificially inflate the match percentage.

MATCH-BASED DECISION RULES

2. 61%–70% MATCH

- Perform moderate enhancement

- Add only believable missing skills

- Focus mainly on:

  - Professional Summary

  - Technical Skills

  - Recent Project

  - Environment section

- Target final alignment around 85%–90%

3. 71%–85% MATCH

- Perform strong ATS optimization

- Add missing keywords naturally

- Enhance project responsibilities

- Improve JD alignment intelligently

- Target final alignment around 90%+

4. 86%–90% MATCH

- Perform minimal optimization only

- Small ATS keyword improvements

- Minor refinements only

- Preserve resume almost completely

5. ABOVE 90%

- No major changes

- Only optional wording or formatting cleanup if needed

STRICT RESUME SAFETY RULES

NEVER:

- Change total years of experience

- Modify employment dates

- Alter company chronology

- Change job titles unless explicitly instructed

- Add unrealistic leadership claims

- Add impossible technology combinations

- Add technologies before their release/adoption period

- Rewrite entire resume unnecessarily

- Overstuff keywords

- Create suspicious career jumps

- Fabricate deep expertise without realistic background support

ALWAYS:

- Preserve original resume format exactly

- Preserve original section order

- Preserve resume structure

- Maintain recruiter-safe realism

- Maintain writing style consistency

- Keep project timeline believable

- Ensure technologies align with market adoption timelines

TECHNOLOGY TIMELINE VALIDATION

Before adding any technology:

- Verify the technology realistically existed during that project timeline

- Avoid outdated/impossible combinations

Examples:

- Do NOT add Kubernetes to very old projects before enterprise adoption

- Do NOT add React in years before mainstream usage

- Do NOT add modern cloud-native tooling to legacy timeline projects unrealistically
